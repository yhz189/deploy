# 国赛冲刺：端云协同与评测计划

## 1. 冲刺定位

当前系统已经完成“摄像头感知 → 事件检测 → 库存更新 → App 展示”的基础闭环。后续冲刺重点不再是盲目扩充识别类别，而是围绕赛题附加分强化：

- 低算力端侧事件检测
- App/云端兜底识别
- 包装食品建档与到期提醒
- 多目标理想场景验证
- 多层冰箱真实部署方案
- 可量化测试报告

核心答辩表述：

> 系统采用端侧优先、云端兜底的协同架构。RK3568 负责低功耗事件检测和基础识别，手机端/云端负责复杂包装文字与低置信度目标的语义增强，最终通过库存数据库形成可查询、可修正、可提醒的完整闭环。

## 2. 端云协同识别方案

### 2.1 数据流

```text
RK3568 摄像头
  -> 运动门控
  -> 稳定后差分定位变化区域
  -> 本地 YOLO/RKNN 识别
  -> 高置信度：直接更新库存
  -> 低置信度/包装/未知：保存变化区域裁剪图
  -> App 拉取裁剪图
  -> 手机 OCR 或云端识别
  -> App 写回识别结果
  -> 后端记录 source=phone_ocr/cloud/manual
```

### 2.2 后端接口

- `/api/package/candidate`：返回包装入库候选裁剪图信息
- `/package/candidate/image`：返回包装入库裁剪图
- `/api/package/confirm`：手机 OCR 识别后写入包装库存
- `/api/package/takeout_candidate`：返回包装取出前后裁剪图信息
- `/package/takeout/ref_image`：取出前裁剪图
- `/package/takeout/new_image`：取出后裁剪图
- `/api/package/takeout`：手机判断包装取出后写回出库事件
- `/api/cloud/confirm`：云端识别兜底结果写回

### 2.3 识别来源记录

库存项保留 `source` 字段：

- `yolo`：板端 YOLO 识别
- `phone_ocr`：手机端本地 OCR
- `cloud`：云端识别兜底
- `manual`：用户手动修正

该字段用于答辩展示不同识别路径，也用于测试报告统计。

## 3. 包装食品与到期提醒

包装库存扩展字段：

- `category`：包装类别，如饮料乳品、调味品、零食、速冻食品
- `expire_date`：到期日期，格式 `YYYY-MM-DD`
- `expire_status`：`none / normal / soon / expired`
- `shelf_id`：层位标记，当前原型为 `single`，多层冰箱可扩展为 `upper/middle/lower`

演示建议：

1. 放入牛奶盒。
2. App OCR 识别名称。
3. 用户补充保质期。
4. 库存页显示包装物品与到期状态。
5. 修改名称/数量/保质期，体现用户纠错闭环。

## 4. 多目标理想场景验证

推荐演示场景：

- 同时放入香蕉和牛奶，二者保持明显间距。
- 香蕉由板端 YOLO 入库。
- 牛奶由手机 OCR 或云端识别入库。
- App 库存页同时出现生鲜食材和包装物品。

边界说明：

- 目标紧贴或遮挡严重时，系统降级为用户修正。
- 本系统强调工程可用性，不夸大极端场景能力。

## 5. 多层冰箱部署方案

结论：一个摄像头不适合可靠覆盖三四层真实冰箱。

原因：

- 层板遮挡导致视野盲区
- 门内瓶架、抽屉和盒装食品容易遮挡
- 不同层高度和视角差异大

真实部署建议：

- 每层布置一个小广角摄像头，或每两层一个摄像头。
- 每路摄像头独立运行事件检测。
- 统一写入同一个库存数据库。
- 库存记录增加 `shelf_id`，App 展示上层/中层/下层。

答辩表述：

> 当前单摄像头原型用于验证核心链路。真实多层冰箱中，层板会造成不可避免的遮挡，因此系统设计为可扩展多摄像头架构，每层独立感知、统一库存管理。

## 6. 演示视频建议

固定 6 个片段：

1. 香蕉放入和取出：展示板端 YOLO 自动库存更新。
2. 牛奶包装放入：展示手机 OCR 入库。
3. 火锅底料包装取出：展示前后裁剪图 OCR 对比和包装出库。
4. 手伸入但不拿东西：展示无效干扰不过账。
5. 同时放入香蕉和牛奶：展示多目标理想条件处理。
6. 包装物品修改保质期/数量：展示用户纠错和到期提醒。

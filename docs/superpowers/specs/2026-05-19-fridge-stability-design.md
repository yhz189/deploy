# 冰箱食材识别系统 — 稳定性优化设计

- 日期：2026-05-19
- 范围：识别稳定性 + 事件鲁棒性优化（对应赛题的「真实事件识别」与「分层识别」）
- 不在本设计范围：模型微调、系统设计文档 / 演示视频 / 答辩 PPT、包装标签 OCR、端云协同、精确到个数的计数

## 1. 背景

RK3568 开发板上的冰箱食材识别系统，YOLOv8n + RKNN 推理 + Flask Web 展示。当前问题：

- **识别不稳定**：同一食材静置时检测结果在 0/1/2 之间跳动，置信度约 0.42。
- **事件误触发**：基于逐帧计数对比的状态机在检测抖动下频繁误判。
- **实测经验**：多物品同时存在时检测计数不准，放入物品后库存大部分时候不更新。

## 2. 问题诊断

根因：现有方案把不可靠的逐帧多目标检测结果直接当真值做计数差分。

- `CONF_THRESH=0.60` 高于模型实际置信度（约 0.42），砍掉大量正确检测 → 0/1 跳动。
- 任何「检测全画面 → 数个数 → 比差异」的方案都依赖多目标检测的准确性，而这恰是模型最弱环节；时间投票也无法挽救稳定的漏检。
- 运动检测（MOG2）已实现但未接入状态机。
- NMS 坐标格式错误：`cv2.dnn.NMSBoxes` 要求 `[x,y,w,h]`，当前传入 `[x1,y1,x2,y2]`。

结论：核心问题是工程链路与算法范式，不是板子算力，也与实现语言（Python/C）无关。算力决定 FPS，不决定精度。

## 3. 方案选择

采用「变化定位」方案：不再检测全画面所有物品，而是

1. 用图像差分定位「哪里变了」；
2. 只对变化区域裁剪后做单物体识别——这是模型最擅长的场景。

赛题说明印证此方向：评委明确推荐「时间窗口多帧确认 + 前后状态比对」作为触发机制设计思路，并鼓励「分层识别」。本方案即该思路的工程实现。

被否决的备选方案：

- 逐帧多目标检测 + 计数差分——实测不可靠（见 §2）。
- 手部跟踪 + 动作识别——属动作识别问题，模型无「手」类别，1 个月内做到答辩级稳定风险过高。
- 固定槽位单格分类——可靠但约束物品摆放，演示场景受限。

## 4. 整体架构

### 4.1 状态机（两态，运动驱动）

```
   ┌──────────┐  连续 N 帧有运动  ┌──────────┐
   │  STABLE  │ ───────────────>│   BUSY   │
   │ 静止·存参考图 │                 │ 操作中·不推理 │
   │          │<─────────────── │          │
   └──────────┘  运动连续消失 K 帧 └──────────┘
        └─ 触发「变化分析」 ─┘
```

- **STABLE**：画面无运动。保存一张「参考图」（当前静止场景）。不做推理。
- **BUSY**：检测到运动（手伸入操作）。不信任检测，只等待运动停止。
- `STABLE → BUSY`：连续 N 帧检测到运动。
- `BUSY → STABLE`：运动连续消失 K 帧 → 操作结束 → 触发一次变化分析。

### 4.2 一次操作的数据流

```
BUSY → STABLE，存新静止图 new
  ↓
[多帧确认] new 连续 M 帧稳定后再继续
  ↓
change_locator: diff(参考图, new) → 变化区域列表
  ↓ 列表为空 → NO_EVENT（整理 / 短暂遮挡被天然滤掉）
逐个变化区域：裁剪 → 模型识别 → 映射到粗类
  ↓
[交叉核对] 消失 × 出现 同粗类 → 判「整理」，不计库存事件
  ↓
派生事件并归一为库存事件 PUT_IN / TAKE_OUT / PARTIAL_TAKE_OUT
  ↓
更新 SQLite 库存（粗类为准，细类作推测）+ 物品位置记忆 + 参考图 ← new
  ↓
回 STABLE
```

关键：推理只在 `BUSY → STABLE` 这一刻进行，且只对裁剪出的小图运行；STABLE / BUSY 期只做廉价的帧间差分。

## 5. 核心算法

### 5.1 `motion.py` — 运动门控

```
is_moving(prev_frame, cur_frame) -> bool
```

灰度化 → `absdiff` → 阈值二值化 → 统计非零像素数，超过阈值即判「有运动」。

### 5.2 `change_locator.py` — 变化定位

```
locate_changes(ref_frame, new_frame) -> list[ChangedRegion]
```

1. 灰度化 ref / new → `absdiff` → 差分图。
2. 阈值二值化 → 形态学**开运算**去噪点、**闭运算**把同一物体碎块连起来。
3. `findContours` → 轮廓 → 按面积过滤（过小=噪点/阴影，丢弃）。
4. 每个保留轮廓 → 一个变化区域 `bbox`。

判断每块是「多了」「少了」还是「换了」——对该 `bbox` 在 ref 与 new 两张图上各裁剪、各运行一次识别：

| ref 裁剪图识别 | new 裁剪图识别 | 判定 |
|----------------|----------------|------|
| 无 | 有食材 | APPEAR（多了） |
| 有食材 | 无 | DISAPPEAR（少了） |
| 有 | 有，不同类 | REPLACE（换了） |
| 有 | 有，同类 | 走 §6 面积判定（整理 / 部分取出 / 忽略） |
| 无 | 无 | 噪声 / 阴影 → 丢弃 |

`ChangedRegion` 输出：`{bbox, kind, fine_class, coarse_class, conf}`。

### 5.3 物品位置记忆

内存维护 `placed_items` 表：`{id, fine_class, coarse_class, bbox, quantity, first_in}`。

- **开机时**做一次全画面检测（多帧投票）给该表与库存播种——这是唯一允许的全画面检测，之后全部走变化定位。
- **APPEAR**：新增一条记录，`bbox` = 变化区域。
- **DISAPPEAR**：按 bbox 重叠度（IoU ≥ 阈值）找到对应记录并删除。取出时不需重新识别——记忆已知该位置原是什么，使 TAKE_OUT 稳定可靠。

### 5.4 分层识别（粗类映射）

模型照常输出 17 细类，系统**对外承诺粗类**，细类作为「推测」展示、可被用户更正。粗类映射：

| 粗类 | 细类 |
|------|------|
| 蔬果 | Apple, Avocado, Banana, Bell pepper, Broccoli, Carrot, Garlic, Lemon, Tomato |
| 生鲜 | Chicken, Eggs |
| 乳品 | Butter, Cheese, Cooking cream |
| 包装食品 | Bread, Hot Sauce, Ketchup |

模型最易混淆的类（Butter/Cheese/Cooking cream → 乳品；Ketchup/Hot Sauce → 包装食品；Tomato/Apple → 蔬果）在粗类层全部成为「不算错」，从根上缓解精度问题。

### 5.5 事件派生 + 交叉核对（整理检测）

一次操作汇总所有变化区域后：

1. **交叉核对**：所有 APPEAR 与 DISAPPEAR 两两配对，若**粗类相同且尺寸相近** → 判「整理」（同一物品挪位），该对不计库存事件，仅记一条「整理」日志。
2. 未配对的 APPEAR → `PUT_IN`；未配对的 DISAPPEAR → `TAKE_OUT`（从记忆查得是什么）。
3. REPLACE → 该位置 `TAKE_OUT(旧)` + `PUT_IN(新)`。

**事件类型口径**：送入 `inventory.py` 的库存事件只有 `PUT_IN` / `TAKE_OUT` / `PARTIAL_TAKE_OUT` 三种。REPLACE 与 §6 的 PARTIAL_PUT_IN 是内部分类，在此处归一映射——REPLACE 拆为 `TAKE_OUT` + `PUT_IN`，PARTIAL_PUT_IN 映射为 `PUT_IN`（`process_event` 的 `_put_in` 已支持同类数量叠加）。派生事件仍为 `('PUT_IN', {'added': {...}})` 形式的元组，`inventory.py` 的 `process_event` 无需改动（其 `EXCHANGE` 分支在新设计下不再被触发，保留为冗余无害）。

## 6. 部分取出策略

§5.2 中「同位置、ref 与 new 都识别出同粗类」的情况，按物体在该区域的**面积**对比细分：

| new 物体面积 vs ref | 判定 |
|---------------------|------|
| 基本相等 | 位置抖动 → 忽略 |
| 明显变小（< 70%） | PARTIAL_TAKE_OUT，按面积比估剩余量 |
| 明显变大 | PARTIAL_PUT_IN（同类追加） |

部分取出难以精确称重：估计值先写入库存，同时在 Web 界面对该条挂「待确认」标记，用户点击可修正数量。可数物（鸡蛋）按「份 / 盒」为单位记，精确到个数列为后续加分项。原则：诚实呈现估计值，不假装精确。

## 7. 边界情况处理

| # | 情况 | 处理 |
|---|------|------|
| 1 | 物品叠放 / 紧挨，diff 块粘连 | 形态学参数 + 面积上限；过大的块标记「待确认」；演示时物品留间距 |
| 2 | 放新物品碰动了旁边的 | 交叉核对：某变化区识别结果与该位置记忆中已有物品一致 → 判位置抖动，忽略 |
| 3 | 阴影也算变化 | 阴影为低对比度变化，二值化阈值滤掉大部分；该块跑识别，识别不出食材即丢弃 |
| 4 | 光照波动 / 自动曝光 | 建议固定摄像头曝光；差分前做全局亮度归一化；全局漂移均匀，面积过滤可滤掉 |
| 5 | 开机初始状态 | 开机做一次全画面检测（多帧投票）播种库存与位置记忆 |
| 6 | 手未移开就采样 | 运动连续消失 K 帧 + new 图多帧确认稳定后才采样 |

## 8. Bug 修复

重写后直接消除：空检测污染状态机、运动门控未接入、`state_color` 残留旧状态名、`test_event.py` 接口误用。

保留代码（`utils.py`）中必须修复：

- `CONF_THRESH` 0.60 → 调低至 0.25~0.35（让裁剪识别有结果，稳定性交由变化定位保证）。
- NMS 坐标格式：传入 `cv2.dnn.NMSBoxes` 前将 `[x1,y1,x2,y2]` 转为 `[x,y,w,h]`。

## 9. 错误处理原则

模型返回 `None`、摄像头读帧失败、裁剪区为空 → 跳过本次，不崩溃、不误更新库存；SQLite 写入失败 → 记日志并保留内存状态。总原则：**宁可漏一次事件，不可错更新库存。**

## 10. 测试方案

- **单元测试**（在 Windows 开发机运行，无需板子 / 摄像头 / 真实食材）：
  - `test_motion.py`：合成两帧，验证有无运动判断。
  - `test_change_locator.py`：合成「货架」底图，程序化加 / 减色块，断言变化区域定位正确。
  - `test_event_detector.py`：脚本化序列（静止 → 运动 → 静止带新色块），识别函数用 mock 替代，断言状态机流转与事件派生正确。
- **集成测试**（板子上）：`main.py` 增加 replay 模式——喂录制视频或保存的帧序列代替实时摄像头，同一段素材可反复测试调参。

## 11. 关键参数

下列参数均需在板子上实测调整，先给初值：

| 参数 | 含义 | 初值 |
|------|------|------|
| `MOTION_DIFF_THRESH` | 帧间灰度差二值化阈值 | 25 |
| `MOTION_AREA_THRESH` | 判定有运动的运动像素数 | 实测 |
| `MOTION_ENTER_FRAMES` (N) | 进 BUSY 所需连续运动帧 | 3 |
| `MOTION_EXIT_FRAMES` (K) | 出 BUSY 所需连续静止帧 | 10 |
| `SETTLE_CONFIRM_FRAMES` (M) | 采样前 new 图稳定确认帧 | 5 |
| `DIFF_THRESH` | 变化定位差分二值化阈值 | 30 |
| `MIN_REGION_AREA` | 变化区域最小面积 | 实测 |
| `CONF_THRESH` | 裁剪识别置信度阈值 | 0.25~0.35 |
| `PARTIAL_AREA_RATIO` | 部分取出面积比阈值 | 0.7 |
| `IOU_MATCH_THRESH` | 位置记忆匹配 IoU 阈值 | 0.3 |
| `SIZE_MATCH_TOLERANCE` | 整理交叉核对的尺寸相近容差 | 0.3 |

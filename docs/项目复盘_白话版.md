---

## 一、这个系统到底在干什么

一句话：**一个装了摄像头的冰箱，能自己看出来你放进去了什么、拿出来了什么，并且实时记一笔账。**

完整流程像这样：

```
摄像头一直拍 → 程序盯着画面
        ↓
有人开冰箱门、伸手进去 → 画面动了 → 程序进入"忙碌"状态
        ↓
人走了、画面不动了 → 程序等几秒确认真的稳定了
        ↓
程序拿"动之前的那张图"和"动之后的那张图"做对比
        ↓
对比出哪块地方变了 → 裁出来交给 YOLO 模型认一认
        ↓
判断出是"放入苹果"还是"取出香蕉" → 记进数据库
        ↓
手机/网页打开就能看到最新库存和事件历史
```

核心思路是**"门控 + 差分"**：不是每一帧都跑 AI 识别（那样太费 CPU），而是先用最简单的"画面有没有动"来判断，只有在"动完了、稳定了"的那一刻才认真比对一次。这样既省算力，又准。

## 二、每个模块实际做了什么

把程序拆成几个零件，每个零件管一件事：

| 模块文件 | 大白话解释 |
|---------|-----------|
| `main.py` | 总指挥。开机、加载模型、一帧一帧喂画面、把结果记账、（可选）在显示器上画窗口。 |
| `motion.py` | "画面动没动"的判断器。把前后两帧灰度图一减，变化的像素多了就是"动了"。 |
| `event_detector.py` | 状态机 + 记忆本。管"稳定→忙碌→沉降→稳定"的切换；还记着每个东西放在画面哪个位置（叫"位置记忆"）。 |
| `change_locator.py` | 对比器。拿"动前图"和"动后图"找出变化的方块区域，再判断这块是"多了东西/少了东西/换了东西/同一个东西"。 |
| `utils.py` | YOLO 工具箱。图片预处理、模型输出后处理、裁剪图识别、19 类清单都在这。 |
| `inventory.py` | 账本。SQLite 数据库，记库存数量和事件历史；新加了"用户手动改数量"的功能。 |
| `web_server.py` | 网页/接口服务。手机浏览器打开能看库存、事件、摄像头画面；也给安卓 App 提供数据接口。 |
| `mock_server.py` | 假后端。开发安卓 App 时不想一直开着板子，就在电脑上跑这个假装是板子。 |

### 状态机三个状态是什么意思

- **STABLE（稳定）**：没人动冰箱，画面安静。这时候程序不停地把当前画面存为"参考图"。
- **BUSY（忙碌）**：有人在动冰箱，画面一直在变。这时候啥也不判断，光等。
- **SETTLING（沉降）**：人好像走了，画面不动了，但还要再观察几秒，确认不是只是手停了一下。确认稳了，就开始对比分析。

为什么要"沉降"这一步？因为人拿东西的时候手会停顿，如果手一停就判断，会误判。多等几帧更稳。

## 三、这个窗口里解决了哪些问题

### 1. 换上了真正能用的 v2 模型 ⭐（最重要）

**之前的问题**：原来那个模型只用 1000 多张图训练，识别效果很差，东西静止放着都认不出来。

**怎么解决的**：在闲鱼上花 10 块钱买了一个训练好的 YOLOv8n 模型（卖家给的训练曲线显示 mAP@0.5≈0.94，19 类水果蔬菜）。把卖家给的 `best.pt` 转成板子能用的 `.rknn` 格式。

**新模型认 19 种**：苹果、香蕉、梨、橙子、菠萝（5 种水果）+ 洋葱、大蒜、甜椒、甜菜、番茄、黄瓜、胡萝卜、茄子、卷心菜、土豆、西葫芦、花椰菜、葫芦瓜等（14 种蔬菜）。

### 2. 模型转换报错 — opset 版本问题

**问题**：把模型转成 RKNN 时报错 `Meet unsupported MaxPool attribute 'dilations'`。

**原因**：板子上的 rknn-toolkit2 1.4.0 太老，不支持 ONNX opset 12 的某个新属性。

**解决**：导出 ONNX 时改成 `opset=11`，转换就过了。

### 3. 取出东西不减库存

**问题**：放入能识别，但把香蕉拿走之后库存不减少。

**原因**：东西被拿走后，那个位置变成了空冰箱背景，模型对"空背景"和"拿走前的香蕉"都识别不出来（裁剪框有偏移、置信度太低）。两边都认不出，程序就当噪声丢掉了，于是漏掉了"取出"事件。

**怎么解决的**（两招）：
- 把置信度门槛从 0.30 降到 0.20（因为香蕉裁剪图实测置信度只有 0.22）。
- **关键招**：变化区域就算两边都认不出，也不直接丢，而是标成 `NOISE`，然后去翻"位置记忆本"——如果记忆本里这个位置原来有东西，那就是被拿走了，照样记一笔"取出"。

### 4. 一串香蕉被当成一个

**问题**：放进去一串香蕉（好几根），系统只记了"放入 1 个香蕉"。

**解决**：识别裁剪图时，统计同一类别有几个检测框，多的话 `count` 就大于 1，按实际个数记账。
**遗留**：如果香蕉挨得太紧，NMS（去重）会把它们合并成一个框，还是会少记。演示时把东西稍微摆开一点。

### 5. 想在显示器上看到实时画面

**问题**：板子接了 HDMI 显示器，但看不到摄像头在干什么。

**解决**：加了 `--show` 参数。`python main.py --show` 会开一个窗口，画面上叠加显示当前状态、帧号、变化区域框、最近事件。窗口里按 `q` 退出。

### 6. 假后端的库存不更新

**问题**：开发安卓 App 用的 `mock_server.py`，手动加事件时库存数字不跟着变，App 库存页测不了。

**解决**：加了 `_apply_to_stock` 函数，加事件时同步更新库存。

### 7. 用户改过的数量被自动识别覆盖 ⭐（本窗口最后解决的）

**问题**：假设冰箱真有 4 个香蕉，但摄像头只认出 3 个，App 上显示 3 个。用户手动改成 4 个。结果板子一重启，重新扫描又把它改回 3 个了。

**根本原因**：板子重启时 `seed_detections` 会重新扫描并把检测到的东西全部"放入"一遍，把用户改过的数据冲掉。

**怎么解决的**：
- 数据库里加了 `has_stock()` 判断。**首次启动**（数据库空）才扫描入账；**重启**（数据库已有数据）只恢复"位置记忆"，绝不动数据库，保护用户改过的数。
- 加了 `POST /api/stock/adjust` 接口，App 可以让用户手动修正数量，会记一条 `MANUAL_ADJUST` 事件。
- 设计上分清楚：**数据库 = 数量真值（用户可改）**，**位置记忆 = 只管东西在画面哪里，不管有几个**。
- 平时运行时识别是"增量式"的（放入 +N、取出 -N），所以用户改过的数不会被覆盖，只有重启那个坑被堵上了。

## 四、还没解决 / 待办

| 事项 | 说明 |
|------|------|
| **板子整体实测没做** | 新模型 + 所有改动还没在真板子上拿真实蔬果跑一遍完整流程。 |
| **参数还没调** | `diff_thresh`、`min_area`、`area_thresh`、`IOU_MATCH_THRESH` 这些阈值都是估的，要拿真实测试数据调。 |
| **紧挨着的东西会少记** | NMS 会合并挨太近的同类物体，演示时物体之间留点缝。 |
| **DEBUG 打印还在** | `main.py` 里还有 `[DEBUG] classify →` 之类的调试打印，演示前清掉。 |

## 五、答辩时怎么讲

### 30 秒电梯陈述

> "我们做的是一个能自动盘点食材的智能冰箱。摄像头实时监控冰箱内部，通过运动检测和图像差分定位变化区域，再用部署在 RK3568 NPU 上的 YOLOv8 模型识别，自动判断食材的放入和取出，维护实时库存。用户可以通过手机 App 查看库存、事件历史和实时画面。"

### 讲解时强调的三个技术亮点

1. **"门控 + 差分"省算力**
   不是每帧都跑 AI 推理，而是用轻量的运动检测做门控，只在画面稳定的关键时刻做一次差分识别。这让一个低功耗嵌入式 NPU 也能扛得住，体现"端侧部署"的工程思考。

2. **三态状态机抗误判**
   STABLE→BUSY→SETTLING→STABLE，"沉降"阶段专门用来过滤"人手中途停顿"的假稳定，提高事件判断准确率。

3. **位置记忆解决"识别不出还要记账"**
   东西被拿走后那块变成空背景，模型认不出。我们用"位置记忆"做兜底——记得这个位置原来有什么，照样能正确记一笔"取出"。这是把 AI 识别和传统视觉规则结合的巧思。

### 现场演示脚本

1. 板子接 HDMI 显示器，跑 `python main.py --show`，让评委看到带状态叠加的实时窗口。
2. 往冰箱（白盒子）里放一个苹果 → 窗口状态变 BUSY → 手撤出 → SETTLING → STABLE → 弹出"放入苹果"。
3. 拿出苹果 → 同样流程 → 弹出"取出苹果"。
4. 掏出手机，打开 App / 网页，展示库存页、事件时间轴、实时摄像头画面三个页面。
5. （加分）在 App 上手动把某个数量改一下，说明"AI 识别 + 人工修正"的容错设计。

### 可能被问到的问题，提前准备

- **"识别不准怎么办？"** → 答：有人工修正功能；而且我们的事件判断是增量式的，单次识别误差不会累积成灾难。
- **"为什么不用云端？"** → 答：端侧部署，数据不出冰箱，保护隐私、不依赖网络、延迟低。
- **"模型是你们训练的吗？"** → 这个要想好怎么说。模型是采购的，但**端侧部署、RKNN 转换、整套事件检测算法、状态机、库存系统都是自己做的**。答辩重点讲后者——你的核心工作量和创新点在系统工程，不在模型训练。

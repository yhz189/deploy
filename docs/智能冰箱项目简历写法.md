# 智能冰箱项目简历写法

## 推荐项目名

```text
RK3568 端侧食材识别与库存管理系统
```

更偏嵌入式的写法：

```text
基于 RK3568 的端侧视觉识别与库存管理系统
```

## 技术栈

完整版本：

```text
RK3568、Linux、Python、OpenCV、RKNNLite、YOLOv8n-RKNN、SQLite、Flask、Android App、pytest
```

弱化 Python 的版本：

```text
RK3568 Linux、OpenCV、RKNNLite、YOLOv8n-RKNN、SQLite、Flask、Android App
```

## 简历正文推荐版

```text
RK3568 端侧食材识别与库存管理系统

项目描述：基于 RK3568 Linux 开发板实现端侧智能冰箱识别系统，通过摄像头采集指定取放区域画面，结合 OpenCV 运动门控、稳定前后帧差分和 YOLOv8n-RKNN 本地推理，识别食材放入、取出、部分取出和位置整理等事件，并通过 SQLite 维护库存数据，支持 Android App 局域网查看与修正库存。

- 基于 RK3568 Linux 开发板完成摄像头采集、运动检测、稳定前后帧差分和变化区域裁剪，采用事件触发式识别方式，减少连续全帧推理带来的无效计算。
- 将 YOLOv8n 食材检测模型转换为 RKNN 格式，并使用 RKNNLite 1.6.0 在 RK3568 NPU 上部署，完成 20 类食材的端侧目标检测与类别映射。
- 设计放入、取出、部分取出和位置整理事件状态机，将视觉识别结果转换为库存增量更新，并通过 SQLite 持久化库存和事件记录。
- 针对不同食材设计混合计量策略：鸡蛋采用目标计数，香蕉/胡萝卜结合 YOLO 类别判断与 OpenCV 颜色分割、连通域面积估计进行库存分级。
- 基于 Flask 提供库存查询、事件记录、摄像头画面、包装食品 OCR 候选和用户手动修正接口，支持 Android App 通过局域网完成库存交互。
- 使用 pytest 对变化区域定位、事件判断、库存更新、包装候选、面积分级和复杂光照增强等核心模块进行测试验证。
```

## 嵌入式 Linux 应用岗位版本

适合投小公司嵌入式 Linux 应用、边缘设备应用、端侧 AI 部署岗位：

```text
RK3568 端侧视觉识别与库存管理系统

技术栈：RK3568 Linux、OpenCV、RKNNLite、SQLite、Flask、Android App

- 在 RK3568 Linux 开发板上搭建摄像头采集、图像处理、NPU 推理和本地库存管理链路，完成板端应用的部署、调试和演示。
- 基于 OpenCV 实现运动门控和稳定前后帧差分，只在取放动作结束后对变化区域进行识别，降低端侧计算压力。
- 使用 RKNNLite 加载 RKNN 模型并调用 NPU 推理，完成模型输入预处理、输出解析、置信度过滤和 NMS 后处理。
- 设计 SQLite 库存管理模块和 Flask REST API，为 Android App 提供库存、事件、摄像头画面和用户修正接口。
```

## 面试不要主动强调的点

- 不要说“全是 Python 写的”，可以说“比赛原型阶段使用 Python 快速打通板端闭环”。
- 不要说“识别准确率很高”，可以说“针对误识别、低光照、包装物品做了工程化兜底”。
- 不要说“覆盖整个冰箱”，应表述为“监控指定取放区域”。
- 不要说“实现大模型识别”，因为本地 VLM 路线后来已经放弃。
- 不要说“深度分割”，应表述为“OpenCV 差分、颜色分割、连通域和面积估计”。

## 一句话介绍

```text
这个项目是我在 RK3568 开发板上做的一个端侧视觉识别系统，核心不是单帧识别，而是把摄像头连续画面转换成库存事件：先用运动检测判断是否发生取放动作，等画面稳定后保存动作前后帧，再用 OpenCV 定位变化区域并调用 RKNNLite 进行 NPU 推理，最后通过事件状态机更新 SQLite 库存，并由 App 展示。
```

## 使用建议

- 这个项目适合投嵌入式 Linux 应用、边缘设备应用、端侧 AI 部署岗位。
- 它不是后续冲 BSP/驱动岗的唯一主项目，后面需要 rkd、驱动或 V4L2 项目补底层能力。
- 简历里重点突出 RK3568、Linux、OpenCV、RKNNLite、事件触发、库存状态机，不突出 Web 业务。

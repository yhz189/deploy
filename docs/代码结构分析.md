## 二、每个文件的实际作用

### `main.py` — 主程序

- 加载 RKNN 模型（`models/fridge_yolo_v2.rknn`）。
- `open_source()`：生成器，支持两种数据源——实时摄像头 / `--replay <目录>` 回放 jpg。
- `seed_detections()`：开机对首帧全画面检测，给位置记忆与库存播种。
- `seed` 逻辑（本窗口改）：首次启动（DB 空）才写库存；重启（DB 已有数据）只恢复位置记忆，**保护用户手动修正**。
- 主循环：逐帧 `detector.update()` → 收事件 → `inv.process_event()` 记账 → 每 30 帧存预览图。
- `--show`：在 HDMI 显示器开 `cv2.imshow` 窗口，叠加状态/帧号/事件/变化区域框，按 `q` 退出。
- 含 `format_event` / `draw_overlay` / `save_preview` 三个可视化辅助函数。
- ⚠ 仍有 `[DEBUG]` 打印（`classify_fn` 与 `locate_fn` 内），演示前应清理。

### `motion.py` — 运动门控

- 仅一个函数 `is_moving(prev, cur, diff_thresh=25, area_thresh=3000)`。
- 灰度差分 → 阈值化 → 统计变化像素数，超 `area_thresh` 判为运动。

### `event_detector.py` — 事件检测器（核心）

- `EventDetector` 类：三态状态机 `STABLE / BUSY / SETTLING`。
  - 切换参数：`enter_frames=3`、`exit_frames=10`、`settle_frames=5`。
- `placed_items`：位置记忆列表，每项 `{id, class_id, fine, coarse, bbox}`。
- `seed()`：播种参考帧 + 位置记忆。
- `update()`：喂一帧，跑状态机；SETTLING 稳定后调 `_analyze()`。
- `_analyze_regions()`：把变化区域翻译成事件，处理 `APPEAR/DISAPPEAR/REPLACE/SAME/NOISE`。
- `NOISE` 兜底：两边都识别不出时，用 `placed_items` 的 IoU 匹配派生 `TAKE_OUT`。
- `_cross_check()`：同粗类、尺寸相近的一出一进配对为"整理"，不计事件。
- 常量：`PARTIAL_AREA_RATIO=0.7`、`IOU_MATCH_THRESH=0.3`、`SIZE_MATCH_TOLERANCE=0.3`。

### `change_locator.py` — 变化定位

- `ChangedRegion` dataclass：`bbox, kind, ref_ident, new_ident`。
- `find_change_regions(ref, new, diff_thresh=30, min_area=400)`：差分 + 形态学开闭运算 + 轮廓提取，返回变化 bbox 列表。
- `classify_regions()`：对每个区域裁剪 ref/new 两图识别，判定 kind：
  - 两边都 None → `NOISE`（本窗口改：之前是直接丢弃）
  - ref 为 None → `APPEAR`
  - new 为 None → `DISAPPEAR`
  - 粗类不同 → `REPLACE`
  - 粗类相同 → `SAME`

### `utils.py` — YOLO 工具箱

- `CLASSES`：19 类清单（见下方 PROJECT_CONTEXT2.md / 文档三）。
- `COARSE_MAP`：细类 → `水果` / `蔬菜`。
- 参数：`IMG_SIZE=640`、`CONF_THRESH=0.20`、`NMS_THRESH=0.45`。
- `letterbox / preprocess`：保持宽高比缩放 + padding，BGR→RGB。
- `postprocess()`：YOLOv8 输出解析。模型输出 `(1, 23, 8400, 1)`（4 坐标 + 19 类）。
  - ⚠ 函数内注释还写着 17/21/3549（旧 17 类模型遗留），**注释过时，逻辑正确**。
- `identify_crop()`：对裁剪图识别，返回 `{class_id, fine, coarse, conf, area, count}`。
  - `count` = 同类检测框个数（本窗口加，支持一串香蕉计数）。

### `inventory.py` — 库存管理

- `InventoryManager`，SQLite，`DB_PATH='inventory.db'`。
- 两张表：`inventory`（库存）、`events`（事件历史）。
- `process_event()`：按 `PUT_IN / TAKE_OUT / PARTIAL_TAKE_OUT / EXCHANGE` 更新库存（增量式）。
- `has_stock()`（本窗口加）：判断 DB 是否已有在库记录。
- `adjust_quantity(name, qty)`（本窗口加）：用户手动修正数量，写 `MANUAL_ADJUST` 事件。
- `get_current_stock / get_recent_events / print_stock / close`。

### `web_server.py` — Web 服务（板子上跑）

- `GET /`：HTML 页面（库存表 + 事件表 + 摄像头，移动端响应式，每 3 秒整页刷新）。
- `GET /camera`：返回 `/tmp/fridge_latest.jpg`。
- `GET /api/stock`：库存 JSON。
- `GET /api/events`：最近 20 条事件 JSON。
- `POST /api/stock/adjust`（本窗口加）：用户修正数量，body `{"name","qty"}`。
- 端口 `5000`，`host=0.0.0.0`。

### `mock_server.py` — 假后端（PC 上跑，App 开发用）

- 模拟板子全部接口：`/api/stock`、`/api/events`、`/camera`（占位图）、`/api/stock/adjust`。
- `/dev/add_event/<etype>/<food>?n=<count>`：手动加事件并同步库存。
- `/dev/reset`：库存与事件恢复到初始基线。
- `_INITIAL_STOCK` / `_INITIAL_EVENTS` 为基线；端口 `5000`。

### `infer_image.py` — 单图推理调试脚本

- 独立工具，对单张图片跑一次检测画框，开发调试用，不参与主流程。

## 三、模块调用关系

```
main.py
 ├── utils.py          preprocess / postprocess / identify_crop / CLASSES / to_coarse
 ├── motion.py         is_moving        ──┐
 ├── change_locator.py find_change_regions / classify_regions
 ├── event_detector.py EventDetector ────┘（构造时注入 motion_fn 与 locate_fn）
 └── inventory.py      InventoryManager

依赖注入关系：
  main.py 构造 detector = EventDetector(is_moving, locate_fn)
    locate_fn 内部调用 → find_change_regions + classify_regions
      classify_regions 接收 classify_fn → 内部调用 identify_crop(model, crop)

web_server.py  ── 独立进程 ── 只依赖 inventory.py（读 SQLite）
mock_server.py ── 独立进程 ── 不依赖任何业务模块（纯模拟，PC 上跑）
```

板子上**同时跑两个进程**：`main.py`（识别+记账，写 SQLite + 写 `/tmp/fridge_latest.jpg`）
和 `web_server.py`（读 SQLite + 读预览图，对外提供网页/API）。两者通过
**SQLite 文件**和**预览图文件**解耦，不直接通信。

## 四、数据从摄像头到网页的完整流程

```
[USB 摄像头]
    │  cv2.VideoCapture，640×480
    ▼
main.py: open_source() 生成器逐帧产出 BGR 图
    │
    ▼
main.py 主循环: detector.update(frame)
    │
    ▼
event_detector.py: is_moving() 运动门控 → 三态状态机
    │  STABLE 期持续刷新 ref_frame
    │  SETTLING 稳定 settle_frames 帧后 ↓
    ▼
event_detector._analyze(settle_frame)
    │
    ▼
change_locator.find_change_regions(ref, new)   差分定位变化 bbox
    │
    ▼
change_locator.classify_regions(...)
    │  对每个区域裁剪 → classify_fn → utils.identify_crop(model, crop)
    │                                    └─ RKNN NPU 推理
    ▼
[ChangedRegion 列表]  kind ∈ APPEAR/DISAPPEAR/REPLACE/SAME/NOISE
    │
    ▼
event_detector._analyze_regions()  → 事件元组列表
    │  含 NOISE 位置记忆兜底、_cross_check 整理配对
    ▼
main.py: inv.process_event(event_type, details)
    │
    ▼
inventory.py: 写入 SQLite (inventory.db)
    │
    │  （另一边）main.py 每 30 帧 save_preview() → /tmp/fridge_latest.jpg
    ▼
═══════════ 进程边界（SQLite 文件 + 预览图文件解耦）═══════════
    │
    ▼
web_server.py: 读 inventory.db + 读 /tmp/fridge_latest.jpg
    │
    ▼
GET /  →  HTML 网页（手机浏览器）
GET /api/stock, /api/events  →  JSON（安卓 App）
GET /camera  →  JPEG 实时画面
    │
    ▼
[手机浏览器 / 安卓 App]
```

## 五、哪些文件能动、哪些不能动

### ✅ 可以放心改

| 文件 | 说明 |
|------|------|
| `main.py` | 可调主循环、可视化、清理 DEBUG 打印。 |
| `mock_server.py` | 纯开发辅助，随便改基线数据。 |
| `web_server.py` 的 HTML 部分 | 网页样式可随意美化。 |
| `docs/` 下所有文件 | 文档。 |
| `tests/` | 改代码就要同步改测试。 |

### ⚠ 改要谨慎（改了必须重跑测试 + 板子实测）

| 文件 | 风险点 |
|------|--------|
| `utils.py` 的参数 | `CONF_THRESH=0.20` 是为 v2 模型实测调过的，调高会漏检取出事件。 |
| `event_detector.py` 的常量 | 状态机帧数、IoU 阈值改了影响事件准确率，需重新调。 |
| `change_locator.py` 的阈值 | `diff_thresh / min_area` 影响变化定位灵敏度。 |
| `inventory.py` 的表结构 | 改 schema 要删旧 `inventory.db` 重建，否则字段对不上。 |

### ❌ 绝对不要动

| 对象 | 原因 |
|------|------|
| `utils.py` 的 `CLASSES` 列表 | 顺序和内容必须与 `fridge_yolo_v2.rknn` 训练时严格一致，改了 = 所有识别结果错位。 |
| `utils.py` `postprocess()` 的输出解析逻辑 | 与模型输出 `(1,23,8400,1)` 张量布局绑定。注释过时可以改，**解析代码不要动**。 |
| `models/fridge_yolo_v2.rknn` | 当前生效模型本体。 |
| `IMG_SIZE=640` | 模型输入尺寸，与 rknn 模型绑定，不能改。 |

## 六、关键参数速查

| 参数 | 值 | 位置 | 含义 |
|------|-----|------|------|
| `IMG_SIZE` | 640 | utils.py | 模型输入尺寸 |
| `CONF_THRESH` | 0.20 | utils.py | 置信度门槛（为 v2 实测调低） |
| `NMS_THRESH` | 0.45 | utils.py | NMS IoU 阈值 |
| `diff_thresh` | 30 | change_locator.py | 变化定位差分阈值 |
| `min_area` | 400 | change_locator.py | 变化区域最小面积 |
| `diff_thresh` | 25 | motion.py | 运动检测差分阈值 |
| `area_thresh` | 3000 | motion.py | 运动判定像素数门槛 |
| `enter_frames` | 3 | event_detector.py | STABLE→BUSY 所需连续运动帧 |
| `exit_frames` | 10 | event_detector.py | BUSY→SETTLING 所需连续静止帧 |
| `settle_frames` | 5 | event_detector.py | SETTLING→STABLE 沉降确认帧 |
| `PARTIAL_AREA_RATIO` | 0.7 | event_detector.py | 部分取出/追加的面积比阈值 |
| `IOU_MATCH_THRESH` | 0.3 | event_detector.py | 位置记忆匹配 IoU 阈值 |
| `PREVIEW_INTERVAL` | 30 | main.py | 每 N 帧存一次预览图 |
| `REGION_SHOW_FRAMES` | 90 | main.py | 分析后变化框持续显示帧数 |
